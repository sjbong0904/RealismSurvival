# 전수 검토 02 — 핵심 생존 루프와 우회 가능성

검토일: 2026-10-21  
검토 기준: 00번 개발 `runClient` 기본 구성, 코드·기본 데이터팩·설정 스펙 정적 추적.  
범위: 갈증, 체온, 생수 섭취, 수영 회복, 물 등급 처리, 필터·증류, 생존 피해와 자연 회복. 계절·작물 자체, 레시피 경제 전체, 실제 난이도 플레이는 별도 회차다.

## 요약

생존 루프는 수치 상태, 서버 권위 처리, 생수 등급, 필터/증류기, 환경 위험과 회복 제한까지 코드상 연결되어 있다. 월드 물의 등급이 병·양동이·기계에 전달되고, 작은 민물 웅덩이를 시간이 지나면 고인물로 바꾸는 구조도 구현되어 있다.

정적 추적에서 우선 조정이 필요한 지점은 **설정 가능한 평가 간격과 시간당 효과가 서로 맞지 않는 것**, **맨손 월드 물 섭취량이 너무 커서 처리된 용기 경로를 쉽게 우회하는 것**, **생존 시스템을 끈 상태에서도 자연 회복이 이전 상태값에 묶일 수 있는 것**이다. 실제 체감·반복 입력·세이브 재접속은 플레이 검증이 필요하며 이번에는 실행하지 않았다.

## 발견사항과 수정 방향

### 02-1 — `tickInterval` 변경에 따라 갈증 회복/침수 회복 비율이 달라짐 (P1)

갈증 소모는 `seconds = interval / 20`을 사용해 경과 시간에 비례한다. 반면 침수 회복은 매 평가마다 고정값 `+0.2`/`+0.05`를 더한다. 기본 20틱에서는 초당 한 번이라 큰 차이가 드러나지 않지만, 허용 최솟값 1틱에서는 초당 20회 적용되어 증류수 침수 회복이 `+4.0`/초, 민물 침수 회복이 `+1.0`/초로 상승한다. 머리 잠김 배율까지 적용하면 각각 `+6.0`/초, `+1.5`/초다. 설정 문구는 평가 간격을 성능/부드러움 조절값으로 설명하므로, 이 변화는 우회 또는 과도한 회복이 된다.

**수정 방향 제안:** 회복값을 `seconds`에 곱하는 초당 수치로 바꾸거나 `tickInterval`을 고정하고 별도의 초당 회복 설정을 둔다. 사용하지 않는 `SWIM_THIRST_RESTORE_PER_SECOND` deprecated 키와 주석(서로 다른 구식 수치가 적혀 있음)을 정리한다.

### 02-2 — 평가 간격이 탈수·극한 체온 피해의 초당 피해량을 바꿈 (P1)

`DEHYDRATION_DAMAGE`, `FREEZE_DAMAGE`, `HEAT_DAMAGE`는 매 생존 평가 회차에 한 번 직접 피해로 적용된다. 기본은 20틱마다지만 설정은 1–200틱을 허용한다. 최소 간격이면 기본 설정보다 피해가 초당 20배 자주 발생하고, 최대 간격이면 초당 적용률이 기본의 1/10로 줄어든다. 반대로 정상 수치가 떨어지는 속도는 elapsed seconds로 계산된다.

**수정 방향 제안:** 피해 설정을 초당 값으로 해석해 평가 시간 `seconds`에 비례시키고, 현재 서버 설정에서 피해량이 평가당인지 초당인지 설명을 일치시킨다. 값의 의미를 유지하고 싶다면 `tickInterval`을 관리자가 게임 밸런스도 바꾸는 고급 항목이라고 명시해야 한다.

### 02-3 — 맨손 월드 물 음용이 병과 동급 회복을 무비용 제공함 (P1, 진행 영향)

빈손 웅크리기 상호작용은 20틱 쿨다운이다. 등급 유체면 `DrinkWaterHandler`가 등급별 병 데이터로 회복/피해량을 정하므로 강의 민물은 1초마다 `+20`이며, 아이템 없이 병과 동급 수분을 반복 획득할 수 있다. 등급 없는 바닐라 물은 `raw_water`의 `+6` fallback을 받는다. 민물의 메스꺼움/허기, 고인물의 독 등 품질 효과는 따라오지만, 물병·필터·증류·운반의 수분 효율 이점이 없어진다. `+6` fallback도 기본 소모 `0.05`/초의 120배지만, 정식 변환이 적용된 월드에서 얼마나 자주 실행되는지는 현재 정적 코드만으로 확인할 수 없다.

**수정 방향 제안:** 직접 음용을 “급한 갈증을 조금 낮추는 위험한 한 모금”으로 둘지, 병과 동급 효율의 편의 기능으로 둘지 의도를 먼저 고정한다. 생존/처리 진행을 보존하려면 수원 음용량을 병 데이터보다 낮추고, 병·필터·증류의 수분 효율이나 휴대성에 차이를 둔다. 직접 음용으로도 초반 생존이 가능해야 한다면 그 경로를 퀘스트와 정보 표시에서 명확히 안내한다.

### 02-4 — 자연 회복 차단 조건이 생존 시스템 토글과 분리되어 있음 (P2)

`NaturalRegenHandler`의 자연 회복 허용 조건은 갈증이 `naturalRegenMinThirst` 이상이고 체온이 위험 구간 밖인지 항상 검사한다. `thirstEnabled=false` 또는 `temperatureEnabled=false`는 생존 루프에서는 각 시스템을 건너뛰지만 이 회복 조건에서는 보지 않는다. 시스템을 끄기 전 낮은 상태가 저장되어 있으면 꺼 둔 동안에도 자연 회복이 막힐 수 있다.

**수정 방향 제안:** 비활성화된 지표는 자연 회복 게이트에서 제외한다. 서버 운영자가 `slowNaturalRegen`만 독립적으로 켜고 싶을 때의 의도는 별도 설정/설명으로 명확히 한다.

### 02-5 — 독립 임계값 설정 사이의 순서 제약이 검증되지 않음 (P2, 설정 오류)

각 체온 경고/중간/심각 임계값은 범위만 제한되고 서로의 순서는 보장하지 않는다. 회복 효과 지속시간 역시 설명상 `tickInterval`보다 커야 하지만 두 값이 독립 설정이다. 관리자가 값을 역전시키면 분기 일부가 도달 불가능해지거나 효과가 다음 평가 전에 사라질 수 있다.

**수정 방향 제안:** 설정 검증에서 순서를 강제하거나, 로드 시 보정/경고를 출력한다. `penaltyEffectDurationTicks > tickInterval` 관계를 보장하거나, 효과 적용 방식을 갱신 시점과 무관하게 바꾼다.

### 02-6 — 주변 열/냉기 기여가 거리·차폐를 구분하지 않음 (P2, 환경 표현)

주변 열/냉기는 설정 반경의 정육면체에서 각 블록 값을 동일하게 더하고 최대/최소값에서 멈춘다. 가까운 토치/화로와 반경 끝의 블록, 벽 너머의 블록이 같은 가중치로 더해진다. 기본값은 반경 4, 열 +12°C, 냉기 -10°C다. 기능상 의도된 단순 모델일 수 있으나, 열원 블록을 여러 개 쌓으면 주변 기온이 쉽게 상한에 도달하는 구조다.

**수정 방향 제안:** 먼저 게임 내 지표/툴팁으로 주변 열·냉기의 기여가 설명되는지 확인한다. 과도한 난방/냉각이 확인되면 거리 감쇠 또는 열원별 강도·차폐 정책을 도입하고, 성능 비용은 12번 관점에서 별도 판단한다.

## 현재 구조의 장점

- 갈증, 음료, 단열, 바이옴별 소모를 데이터팩/서버 설정으로 조정할 수 있다.
- 서버가 상태를 계산하고 필요한 값만 소유 클라이언트에 동기화한다.
- 물 등급이 병·양동이·얼음·월드 블록·기계 처리에 공통 모델로 전달된다.
- 필터와 증류기는 입력 수량, 빈 용기, 출력 공간, 카트리지/연료가 있을 때만 진행하도록 데이터 경로가 갖춰져 있다.
- 소형 민물 웅덩이 정체 시스템은 크기 임계, 최초 관찰 시각 저장, 주변 청크 순환 처리로 구현돼 있다.

## 교차 회차 연결

- 03: 계절별 물·음료·농사 관점에서 수분 회복원과 식량 자립을 함께 본다.
- 04: 필터 카트리지, 연료, 소금 부산물 및 처리 시간의 재료 가치를 본다.
- 09: 강·습지·해안·소형 웅덩이의 월드 배치와 실제 자원 접근성을 본다.
- 11: 갈증/체온 표시, 열원 정보, 처리기 진행/출력 상태의 사용자 설명을 본다.
- 12: 주변 블록 스캔과 웅덩이 검사 부하를 본다.
- 14: 위 우선 문제를 수정한 뒤 설정 간격별, 생수 품질별 실제 플레이를 회귀 확인한다.

## 회차 결론

코드상 생존 루프는 폭넓게 구현되어 있으나, 사용자 조정 가능한 `tickInterval`이 회복/피해 비율을 깨고 월드 물 음용의 회복량이 병/처리 루프를 압도할 가능성이 크다. 수정 우선 제안은 **02-1 시간 보정**, **02-2 피해 시간 보정**, **02-3 맨손 음용 수치와 등급 차별화**, **02-4 토글 일관성** 순이다. 이 네 가지는 게임 체감 밸런스 확인 전에 코드/데이터 의미부터 정리할 수 있다. 이번 회차는 분석과 수정 방향만 기록했으며 코드를 바꾸거나 테스트를 실행하지 않았다.
