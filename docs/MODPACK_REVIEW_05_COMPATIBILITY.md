# 전수 검토 05 — 외부 모드 연결·충돌 위험

검토일: 2026-10-21  
검토 기준: 기본 개발 실행 의존성, 모드 메타데이터/믹신, 조건부 데이터, 코드의 선택 의존성 정적 추적. 정식 배포 모드 목록과 모든 버전 조합은 13번에서 확정한다. 게임을 부팅하거나 멀티 모드 회귀 테스트를 하지 않았다.  
범위: Minecraft/NeoForge와 선택 모드의 연결 구조, 선택 의존성 누락 시 안전성, 공존 충돌 위험, 조건부 데이터, Oritech·Serene Seasons·Sodium·Fish of Thieves·상점 통합.

## 요약

코어는 직접 참조 대신 `ModCompat`의 모드 존재 확인과 리플렉션을 사용해 주요 선택 의존성을 분리했다. Serene Seasons는 리플렉션 브리지, Fish of Thieves와 Sodium은 별도 `required:false` 믹신 설정, 레시피/음식 정의는 모드 로드 조건으로 가드한다. 브리지 레시피 82개를 훑어 외부 아이템 namespace가 해당 모드의 로드 조건 없이 쓰이는 정적 사례는 찾지 못했다.

가장 큰 리스크는 기능이 넓은 필수 믹신 설정의 Minecraft/NeoForge 업데이트 민감성, 상점 통합이 Q Shop 내부 클래스/필드/열거형에 리플렉션으로 의존한다는 점, Serene Seasons API 조회 실패와 “모드가 존재함” 판정을 혼용해 커스텀 계절 처리를 꺼버릴 수 있다는 점이다. 현재 `runClient`에 들어오는 일부 라이브러리는 배포 의존성과 다를 수 있으므로 이번 결론은 개발 설정 기준이다.

## 확인한 연결 구조

- `build.gradle`은 Aquaculture/Fish of Thieves/Cloth Config, Farmer’s Delight, Serene Seasons/GlitchCore, Sodium/Iris, Pipez·Large Fluid Tank, 월드/지도/QoL, FTB 퀘스트·팀, Oritech 및 상점 스택 등을 `localRuntime`에 선택적으로 포함한다.
- Fish of Thieves용 3개 믹신과 Sodium용 3개 믹신은 각각 별도 설정으로 선언되고 `required:false`, `defaultRequire:0`이다. 기본 믹신 설정은 필수이며 `defaultRequire:1`이다.
- Farmer’s Delight 및 Fish of Thieves 식품/작물/조리법은 JSON `mod_loaded` 조건을 사용한다. 브리지 아이템 레시피의 외부 namespace/모드 조건도 일치한다.
- Oritech 물 대체 레시피는 Oritech와 Realism Survival 존재 조건을 가지며, FTBMaterials/EnderIO 원본 조건을 보존한다. 04번에서 25개 원본 대비 재료·산출·시간 일치를 확인했다.
- 상점 경로는 Easy NPC의 `rs_shop` 태그 NPC 상호작용 → Q Shop `supply_post`; SG Economy 지갑이 있으면 `coins` 통화 브리지가 연결되는 구조다. Q Shop 내부 Java 타입/필드를 리플렉션으로 찾는다.
- Create는 26.1 빌드가 준비되기 전까지 개발 프로퍼티에서 켜면 명시적으로 실패하게 해 두었다. 현재 26.1 자동화 연결은 Pipez·대형 유체 탱크 중심으로 설명된다.

## 발견사항과 수정 방향

### 05-1 — 필수 코어 믹신 묶음이 광범위하고 업데이트 민감함 (P1, 회귀 위험)

필수 설정에 물/빙결/산호/가마솥/양동이/용광로/블록 이름/청크 생성/상점 NPC 등 여러 바닐라 클래스와 메서드 주입이 들어 있고 `defaultRequire:1`이다. 각 주입 실패를 조용히 무시하지 않는 것은 일부 동작 누락을 빨리 발견하는 이점이 있지만, 마이너 Minecraft/NeoForge 변경에도 전체 모드 부팅을 실패시킬 수 있다. 이 설정은 선택 모드가 없어도 코어 로드에 필수다.

**수정 방향 제안:** 믹신별 영향 기능과 최소 지원 Minecraft/NeoForge 버전을 업데이트 체크리스트에 둔다. 선택 모드 전용 주입은 FOT/Sodium처럼 격리한다. 바닐라 동작에 큰 영향을 주는 수계 주입은 변경 때 GameTest/클라이언트/전용 서버 회귀 대상에 포함한다. 단순히 `required:false`로 바꾸기보다 실패 시 손실되는 기능과 허용 가능성을 개별 결정한다.

### 05-2 — Serene Seasons가 로드됐지만 브리지 조회가 실패하면 작물 규칙을 생략할 수 있음 (P1, 데이터 경계)

`CropGrowthHandler`는 `SereneSeasonsBridge.present()`만 보고 자체 계절 성장을 건너뛴다. 이 값은 모드 존재와 reflection 메서드 해석 성공으로 정해진다. 이후 특정 월드의 현재 계절 조회가 실패해 `SeasonCalendar`가 자체 달력으로 대체되어도, 작물 핸들러는 Serene Seasons가 있다고 판단해 자체 계절 배율을 계속 생략할 수 있다. 계절 표시와 작물 효과가 분리될 가능성이 있다.

**수정 방향 제안:** `present()` 대신 해당 레벨의 계절 스냅샷이 성공했는지 공유하는 결과를 기준으로 작물 규칙을 선택한다. 외부 계절 조회 실패를 로그에서 한 번 명확히 보고 자체 달력으로 일관되게 전환한다. 이 항목은 03-1의 적용 범위 문제와 함께 수정/검증한다.

### 05-3 — 상점 브리지는 외부 구현 세부사항을 리플렉션으로 사용함 (P1, 버전 민감)

상점 생성은 `com.qshop.shop.ShopManager`, `Shop`, `ShopEntry`, `ShopEntryType`, `LimitReset`, `ShopTab`의 이름·생성자·public 필드·메서드에 의존한다. Q Shop에서 내부 구조/열거값을 바꾸면 공급소 재생성 시점에 예외가 날 수 있다. SG Economy 통화 연동도 별도 브리지 경로다. 선택 모드 부재 때 로딩은 피하지만, 사용 중인 특정 Q Shop 버전에 대한 호환 확인은 정적 이름 추적으로만 끝난다.

**수정 방향 제안:** 지원 Q Shop/SG Economy 버전을 좁혀 문서와 팩 잠금 버전에 맞춘다. 시작 시 기능 확인을 한 번 수행하고, 실패하면 공급소 생성/열기를 안전하게 비활성화하고 명확한 로그를 남긴다. 공개 API가 가능한지 확인하고, 없다면 해당 버전의 간단한 서버 시작/계절 변경 스모크 시나리오를 14번에 넣는다.

### 05-4 — 배포 구성과 개발 런타임의 모드 조합 차이가 큼 (P1, 재현성)

`localRuntime`는 실행 편의를 위한 의존성으로, 소비자 의존성을 선언하는 `implementation`과 다르다. 개발 `runClient`는 다수 선택 모드/라이브러리를 받지만 이 사실만으로 정식 팩에 같은 버전이 포함됐거나 모두 함께 지원된다고 판단할 수 없다. 00번에서도 `run/mods`는 비어 있고 배포 산출물 경로는 미확정으로 남았다.

**수정 방향 제안:** 13번에서 모드 목록·버전 잠금·필수/선택·클라이언트/서버 범위를 정식 프로필 하나로 확정하고, 호환 점검표를 그 조합에 한정한다. 개발 전용 Sodium/Iris·API 데모와 실제 팩 모드를 혼동하지 않도록 구분한다.

### 05-5 — 선택 모드별 기능 저하/노출 상태를 플레이어가 알기 어려울 수 있음 (P2, 일관성)

Aquaculture/FoT/FD/Serene Seasons/Pipez/Q Shop의 부가 연결은 특정 모드가 있을 때만 나타난다. 레시피 조건은 안전하지만 모드 하나를 제외하면 특정 퀘스트 과제·아이템 설명이 남을 수 있다. 문서에는 일부 연결이 “계획”이라고 적혀 있으나 코드/브리지 데이터는 이미 동작을 구현한 항목도 있다.

**수정 방향 제안:** 기본팩은 모든 계획 모드가 필수인지 선택인지 명시하고, 선택 조합을 지원할 경우 퀘스트/상점/JEI에서 참조하는 아이템 존재를 함께 조건화한다. 문서의 “계획”, “현재 지원”을 구현 상태와 맞춘다(13번).

## 양호한 구조

- 브리지/음식 JSON에서 모드별 `mod_loaded` 조건을 사용한다. 조사한 82개 아이템 브리지에서 외부 아이템을 조건 없이 참조하는 사례는 발견하지 못했다.
- Serene Seasons 및 GUI 상점 연결은 리플렉션/선택 의존성으로 직접 클래스를 필수 의존성으로 만들지 않는다.
- 선택 의존성용 믹신 설정을 코어와 별도로 두고 `required:false`를 사용한다.
- Oritech 호환 레시피는 외부 모드 조건을 보존하고 원본의 재료/수율을 정적으로 보존한다.

## 회차 결론

조건부 데이터와 optional mixin 분리는 전반적으로 잘 구성되어 있고, 브리지 아이템의 모드 누락은 방지된다. 우선순위는 **05-2 Serene Seasons API 실패 시 계절 효과 일관성**, **05-3 상점 리플렉션의 지원 버전/실패 처리**, **05-4 공식 배포 구성 확정**이며, 코어 필수 믹신은 각 버전 업데이트에서 집중 회귀 대상이어야 한다.
