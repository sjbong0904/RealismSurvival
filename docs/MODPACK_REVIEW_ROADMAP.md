# 모드팩 전수 검토 로드맵

## 목적과 검토 원칙

이 문서는 Realism Survival 모드팩을 한 번에 한 관점씩 깊게 검토하기 위한 진행 순서와 공통 절차를 정리한다. 검토 범위는 커스텀 모드와 애드온, 외부 모드, 설정·데이터팩·레시피 브리지, 퀘스트, 한글화, 배포물과 실제 플레이 경험을 모두 포함한다.

00–14번 정적 검토 문서는 완료되었다. 마지막 통합 시나리오: [전수 검토 14 — 통합 진행 시나리오·회차 간 회귀 위험](MODPACK_REVIEW_14_INTEGRATION.md). 런타임 플레이와 배포 프로필 검증은 아직 수행하지 않았다.

전체 회차 상태와 결정 기록은 [전수 검토 진행 기록](MODPACK_REVIEW_LOG.md)에서 관리한다. 검토 결과의 실행 순서는 [00–14 통합 패치 계획](MODPACK_PATCH_PLAN.md)에서 관리한다. 각 회차는 별도 결과 문서를 만들고, 결과·수정 방향·논의된 결정·수정 후 재검토를 함께 남긴다.

각 회차는 표에 적힌 관점 하나만 판정한다. 다른 관점에서 발견한 문제는 현재 회차의 결론에 섞지 않고 후속 검토 항목으로 기록한다. 앞 단계의 사실 확인 결과는 다음 단계에서 재사용하되, 코드나 데이터가 바뀌면 영향을 받는 단계만 다시 확인한다.

검토는 다음 순서로 진행한다.

1. 현재 작업물의 기준선과 증거를 고정한다.
2. 구성요소별 기능과 생존 시스템을 확인한다.
3. 아이템·레시피·모드 연결과 성장 흐름을 확인한다.
4. 퀘스트, 경제, 월드, UI의 실제 사용성을 확인한다.
5. 서버·저장·성능·배포 위험을 확인한다.
6. 발견사항을 수정한 뒤 영향 범위에 한해 재검토하고 통합 플레이 검증으로 닫는다.

플레이 시간 목표는 튜토리얼 수준의 핵심 안내가 약 60시간 안팎에 걸쳐 자연스럽게 제공되는 것과, 전체 수집·숙련·완성에는 그보다 훨씬 긴 플레이가 필요한 것을 구분해 판단한다. 60시간을 전체 콘텐츠 완료 시간으로 간주하지 않는다.

## 매 회차의 표준 절차

1. **범위 고정**: 이번 회차의 단일 관점, 검토할 경로와 제외할 인접 관점을 한 문장으로 정한다.
2. **증거 수집**: 코드·설정·데이터·문서·게임 내 동작 중 무엇을 확인했는지 파일 경로, 레시피 ID, 퀘스트 ID, 버전 또는 재현 단계로 남긴다.
3. **기대 흐름 정의**: 해당 기능이 어떤 플레이어 문제를 해결하고, 어느 진행 단계에서 어떤 결과를 내야 하는지 먼저 적는다.
4. **사례별 추적**: 대표 정상 경로, 초보자 경로, 경계 조건, 실패/우회 경로를 살핀다. 모든 아이템/퀘스트를 표본만으로 대체하지 말고, 전수 목록을 만든 뒤 위험도 높은 항목과 전체 반복 항목을 나눈다.
5. **판정**: 의도대로 동작하는지, 맥락에 자연스러운지, 플레이어가 알아차릴 수 있는지, 비용·보상이 맞는지 각각 구분한다.
6. **기록과 인계**: 이번 관점의 발견사항을 닫고, 인접 영역에서 나온 관찰은 다음 회차 번호와 함께 대기 목록에 넣는다.
7. **회차 종료**: 미확인 범위, 증거 수준, 확신도와 후속 조치가 명시되었을 때만 회차를 완료 처리한다.

## 회차별 문서화 규칙

- 파일 이름은 `docs/MODPACK_REVIEW_<번호>_<주제>.md` 형식으로 쓴다. 번호는 표의 회차 번호를 두 자리로 적는다. 예: `MODPACK_REVIEW_00_BASELINE.md`.
- 회차 문서에는 최소한 검토일·범위, 요약 결론, 기준선/근거, 발견사항, 수정 방향 제안, 미확인 항목, 후속 회차 연결을 넣는다.
- 수정 방향은 **제안**과 **합의된 결정**을 구분한다. 사용자가 결정하지 않은 안을 확정 사항처럼 기록하지 않는다.
- 방향이 논의되면 진행 기록의 해당 행과 회차 문서에 결정 날짜·내용·상태를 적는다. 적용 후에는 변경 파일과 재검토 결과를 같은 문서에 덧붙인다.
- 아직 합의되지 않았거나 증거가 부족한 항목은 `논의 대기` 또는 `미확인`으로 남기고, 다음 관점 검토 결과와 섞지 않는다.
- 한 회차의 검토 문서는 해당 관점의 정본이다. 로드맵에는 절차와 링크만 두고 상세 발견사항을 중복 기재하지 않는다.

## 발견사항 기록 형식과 우선순위

각 발견사항은 아래 형식을 사용한다.

```text
ID / 우선순위 / 검토 회차
위치: 파일·레시피 ID·퀘스트 ID·화면 또는 재현 단계
현재 동작:
기대 동작과 근거:
플레이어 영향:
재현 조건과 증거:
권장 조치:
확신도: 높음 / 보통 / 낮음
연관 후속 회차:
```

우선순위는 다음 기준으로 통일한다.

- **P0 차단**: 진행 불가, 월드/데이터 손상, 심각한 중복 지급·경제 붕괴, 시작 또는 핵심 루프 실패.
- **P1 높음**: 다수 플레이어의 진행이나 핵심 시스템 이해를 막거나, 균형을 크게 무너뜨리는 문제.
- **P2 보통**: 우회 방법은 있지만 반복적으로 불편하거나, 특정 경로/모드/퀘스트의 완성도를 낮추는 문제.
- **P3 낮음**: 문구·표시·선택적 경로의 다듬기처럼 영향 범위가 좁은 개선.

“취향 제안”과 재현 가능한 결함은 분리한다. 제안에는 모드팩 컨셉, 예상 플레이어, 비용 대비 효과를 붙여 필수 수정처럼 보이지 않게 한다.

## 전수성을 확보하는 방법

- 모드, 레시피, 퀘스트, 번역 키, 설정 파일, 상점 상품을 기계적으로 목록화하고 검토 대상 수와 완료 수를 기록한다.
- 각 회차의 완료 기준은 “문제를 몇 개 찾았는가”가 아니라 “목록의 어느 범위까지 어떤 증거로 확인했는가”로 둔다.
- 높은 위험의 경로는 처음부터 끝까지 직접 추적하고, 나머지는 전체 데이터의 정적 비교와 명시된 표본 플레이를 조합한다.
- 선택 모드가 있으면 설치 조합별 차이를 기록하고, 기본 배포 조합과 선택 조합을 혼동하지 않는다.
- 코드·레시피·퀘스트 수정이 기준선 이후 발생하면 변경 파일을 영향 회차에 연결해 재검토한다.
- 보고서와 수정안은 한국어로 유지하고, 실제 게임 내 식별을 위해 코드 ID·아이템 ID·설정 키는 원문을 함께 적는다.

## 최종 완료 기준

전체 검토는 아래 조건을 모두 만족할 때 마무리한다.

- 00–14회차 각각에 범위, 확인된 수량/경로, 증거, 미확인 항목, 결론이 기록되어 있다.
- P0/P1 항목은 수정 후 영향받는 회차에서 재검토되었거나, 해결되지 않은 이유와 영향이 명시되어 있다.
- 중요 레시피·아이템·퀘스트·상점 거래·진행 경로에 출처와 사용처 또는 완료 상태가 연결되어 있다.
- 핵심 싱글/멀티플레이 시나리오의 환경과 결과를 재현할 수 있다.
- 배포 구성과 문서가 일치하며, 남은 P2/P3 또는 취향 제안은 우선순위와 함께 별도 목록으로 인계되어 있다.

## 권장 진행 단위

한 회차에서 모든 발견사항을 즉시 고치려고 하지 않는다. 먼저 해당 관점의 전수 목록과 평가를 완성하고, 그 회차의 조치 목록을 확정한 뒤 구현 단계로 넘어간다. 수정은 관련 문제를 묶어 적용할 수 있지만, 검증은 원래 발견된 관점에서 다시 하고 연쇄 영향이 있는 인접 회차도 갱신한다. 다음 회차로 넘어갈 때에는 이전 회차의 미해결 항목을 숨기지 않고 참조한다.
