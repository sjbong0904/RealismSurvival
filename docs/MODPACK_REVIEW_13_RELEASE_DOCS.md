# 전수 검토 13 — 배포·업데이트·라이선스·문서

- 검토일: 2026-10-21
- 범위: 실제 실행/배포 프로필, 팩 조립 경로, 의존성 고정, 설치·업데이트 문서, 한국어/퀘스트 문서의 정본과 오래된 중복 계획
- 증거 수준: Gradle·리소스·팩 디렉터리·문서 정적 확인. 새 클린 인스턴스 설치와 배포 아카이브 재현은 미실행.

## 요약 결론

현재 저장소는 Realism Survival 모드 개발 프로젝트와 `runClient`용 조합을 갖추고 있으나, 외부 모드 목록·버전·설정·데이터팩·리소스팩을 하나의 설치 가능한 배포팩으로 묶는 정식 manifest/조립 산출물은 확인되지 않았다. 따라서 설치 안내와 실제 배포 대상은 아직 고정되지 않았다.

문서에는 최신 구현과 맞는 기록도 있지만, 핵심 설계 문서 `MODPACK.md`에 과거 계획과 현재 상태가 섞여 있다. 특히 WDA 포함 계획, BoP 태그 미완료 문구, 1,000개 이상 퀘스트 목표가 실제 실행 구성 및 현재 퀘스트 수와 상충한다. 이 회차에서 정본 상태 요약을 문서 앞부분에 보강하고 두드러진 상충 표현을 수정했다. 나머지 장기 설계/역사 기록은 삭제하지 않고, 정본과 과거 제안을 구분하도록 정리 대상으로 기록한다.

## 확인된 구성 경계

- `build.gradle`은 `runClient`/`runServer`용 `localRuntime`에 개발·팩 콘텐츠 의존성을 조건부로 더한다. `localRuntime`은 개발 실행용이며 모드 JAR 소비자에게 외부 팩 모드를 함께 배포하지 않는다.
- Oritech, Athena, GeckoLib, Q Shop, SG Economy, Easy NPC, Celesthyd는 `libs/`의 로컬 JAR로 실행 프로필에 들어간다. 다른 다수 모드는 Gradle 좌표로 로컬 런타임에서 해석한다.
- 실행 명령은 있으나, 확인한 저장소 경로에는 Modrinth/CurseForge 배포 manifest, packwiz 인덱스, 전체 클라이언트/서버 팩 조립 및 검증 절차가 없다. `pack/`은 설정, 데이터팩, 번역 소스 및 리소스팩을 담는 소스 구조다.
- 한국어 리소스팩은 `pack/resourcepacks/rs-korean`에 산출되어 있고, 스크립트가 `run/resourcepacks`에도 복사한다. 배포 설치기가 기본 활성화하는 설정은 확인되지 않는다.
- 라이선스/자산 출처 문서가 `docs/THIRD_PARTY_ASSETS.md`와 의약품 애드온의 별도 자산 문서로 존재한다. 모든 외부 모드의 라이선스·재배포 허용을 집계한 최종 배포 표는 이번 확인 범위에 없다.

## 발견사항

### 13-1 / P1 / 정식 배포 단위가 정의되어 있지 않음

- 현재 동작: 개발 Gradle 프로필은 옵션으로 여러 외부 모드를 추가하지만 소비자용 모드팩 manifest나 완성된 `mods/config/resourcepacks/datapacks` 묶음을 만들지 않는다.
- 플레이어 영향: 새 플레이어가 어떤 모드 파일·버전을 설치해야 하는지 하나의 재현 가능한 목록으로 알 수 없다. 클라이언트 전용/서버 필수 구분도 개별 문서와 빌드 옵션에 흩어져 있다.
- 권장 조치: 배포 대상을 먼저 하나로 고정한다(예: Modrinth pack 또는 packwiz). 정확한 모드 파일 ID/해시, 필수/선택/클라이언트 전용, 설정·월드 데이터 적용, 리소스팩 기본 활성화 및 업데이트 정책을 manifest로 관리한다. 실제 새 인스턴스 설치를 재현하기 전에는 배포 완료로 표기하지 않는다.
- 확신도: 높음.

### 13-2 / P1 / `docs/MODPACK.md`가 과거 계획과 현재 구현을 한 문서에서 혼합

- 예시: WDA를 초기 구성 및 챕터 콘텐츠로 적은 부분과 NeoForge 26.1 미지원으로 보류한다는 부분이 공존한다. BoP 기후 태그 구현 완료와 “데이터팩 아직” 표현이 함께 존재한다. 현재 퀘스트/도감 개수와 다른 설계 목표(1,000~1,100)를 현재 팩 목표처럼 읽을 수 있다.
- 조치: 문서 첫머리에 구현 상태 정본을 보강하고, 명백히 갱신 가능한 WDA/BoP 상충 문구를 고쳤다. 세부 장기 계획은 13번 보고서 기준의 현재 상태와 대조해 “과거 설계안” 표기를 추가하거나 별도 설계 기록으로 분리해야 한다.
- 확신도: 높음.

### 13-3 / P2 / 한국어 퀘스트 문서 경로가 여러 개라 정본이 혼동됨

- 확인: 생성기/퀘스트 설정은 `tools/quest_v1/` 및 `pack/config/ftbquests/`를 사용한다. 동시에 `Realism Survival — 퀘스트 진행표 v1.md`, `QUEST_IMPL_NOTES.md`, `QUEST_REDESIGN_PROMPT.md`, `QUEST_UX_AUDIT.md`, `QUEST_LIST.md`와 CSV가 있다. 각각 설계·요약·감사·내보내기 목적이 다르지만 상단 안내에서 최신성/정본 관계가 일관되게 드러나지 않는다.
- 권장 조치: `pack/config/ftbquests/README.md`와 실제 생성기를 정본으로 지정하고, 보고서/스냅샷은 “생성 시점”을 표기한다. 이미 수행한 재설계 프롬프트나 Phase 0 메모는 재사용하지 않을 계획이면 archive로 이동하거나 삭제한다. 원본을 삭제하기 전에는 링크와 도구 사용 여부를 전수 검색한다.
- 확신도: 높음.

### 13-4 / P2 / 언어 및 번역 검증이 모드 버전 기준으로 재현되지 않음

- 현재 동작: 번역 오버레이 생성/비교 스크립트가 있으나, 배포 목록과 동기화된 한 번의 결과표 또는 신규 인스턴스 적용 절차는 문서화되지 않았다. 스크립트의 JAR 이름 검색과 실제 설치 파일이 달라질 수 있다.
- 권장 조치: 배포 manifest에서 로케일 검사 입력 JAR을 제공하고 누락 키 수를 기록한다. en_us에 한국어 본문이 있는 퀘스트 파일을 정책에 맞게 분리하고 리소스팩 기본 적용을 설치 가이드에 반영한다.
- 확신도: 높음.

### 13-5 / P2 / 재배포 라이선스 집계는 팩 단위로 완료 여부를 확인해야 함

- 현재 동작: 커스텀 자산의 크레딧 문서는 존재하지만, 개별 외부 모드 파일을 배포물에 포함·재배포할지와 각 모드의 이용 조건을 망라한 목록은 확인되지 않았다.
- 권장 조치: 선택한 플랫폼이 모드 파일 다운로드를 처리하는 방식과 각 제작자 이용 조건에 맞춰 재배포/링크 여부를 기록한다. 커스텀 모델·텍스처·폰트·번역 등 직접 포함 자산은 출처, 저자, 라이선스를 파일 단위로 점검한다.
- 확신도: 확인 문서 존재는 높음, 모든 모드 조건의 충족 여부는 미확인.

## 문서 정리 방향

- `README.md`: 모드 개발 프로젝트와 플레이 가능한 배포팩을 구분하고, 현재는 개발 프로필 기준임을 안내한다.
- `MODPACK.md`: 현재 구성/퀘스트 수/상태를 정본 표로 유지하고 오래된 후보·예정 챕터는 과거 설계 또는 보류로 표시한다.
- 퀘스트 문서군: 정본 생성기·팩 설정, 검토 로그, 생성 스냅샷/역사 문서를 구분한다. 비슷한 제목이라도 먼저 링크·입력 관계를 확인하고 정리한다.
- `KOREAN_LOCALES.md`: 번역 소스·산출 위치 및 클린 설치 적용 과정을 현재 스크립트와 배포 방식에 맞춰 갱신한다.
- 오래된 수치와 경로를 무조건 지우기보다, 사용 중인 데이터인지 확인하고 기록 보존/삭제를 나눠 처리한다.

## 미확인·후속 조치

- 배포 플랫폼과 실제 대상 프로필(클라이언트/서버, 기본 QoL/콘텐츠 포함)을 확정하지 않았다.
- 새 인스턴스에서 설치, 첫 실행, 리소스팩 적용, 기존 월드 업데이트를 재현하지 않았다.
- 외부 모드 전체의 재배포 조건과 제3자 자산 attribution은 최종 배포 목록에 맞춰 재검토가 필요하다.
- 14번은 현재 개발 프로필 기준의 연결 시나리오이며, 배포 프로필이 정해지면 같은 시나리오를 그 조합에서 반복해야 한다.
