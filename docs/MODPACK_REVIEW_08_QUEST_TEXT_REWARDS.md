# 전수 검토 08 — 퀘스트 문안·과제·보상

검토일: 2026-10-21  
검토 기준: 현재 생성 원본(tools/quest_v1/)과 한국어 퀘스트 진행표를 대조했다. 반복 도감 문구는 생성 규칙까지 확인했다. 대량의 보상 수량을 실제 플레이 경제로 실측하지 않았다.  
범위: 제목/설명 자연스러움, 설명과 과제 감지의 일치, 제출·보유 요구의 명료성, 수동 체크 항목, 초·중·후반 보상 타이밍.

## 요약

메인 진행 퀘스트는 대체로 목표 아이템과 다음 행동을 설명하고, 제출/보유 구분도 진행표에 표시된다. 자동 감지가 안 되는 화면 확인·기계 연결은 체크마크와 문구로 처리한 곳이 보인다. 그러나 이 방식은 실행 자체를 확인하지 않으므로 “보상 조건을 실제로 달성했다”는 신뢰도가 약하다. 특히 기계/유체 연결처럼 시스템을 익히는 핵심 목표는 가능한 감지 증거로 바꾸는 편이 낫다.

가장 넓은 문안 문제는 작물·음식·물고기·바이옴·생물·광물·유물 도감 항목에 자동 생성된 “이름을(를)”이 반복된다는 점이다. 현재 진행표에서 540개 설명에 이 표기가 보인다. 한국어로 자연스럽지 않으며, 각 이름의 받침에 맞춘 조사가 필요하다. 또 일부 목표 설명은 실제 task가 측정하는 행동과 다르다. 보상 측면에서는 초반 보급이 넉넉하도록 설계됐지만, 완벽 단계 최종 보상은 모드팩 개요가 말하는 기념성/비전투 보상과 달리 금·경험치 자원에 치우친다.

## 발견사항

### 08-1 — 자동 생성 도감 설명의 조사 표기가 부자연스러움 (P1, 540개)

도감 생성기에서 “이름을(를) 보유/제출/방문/처치하세요” 형식을 고정한다. 현재 퀘스트 목록에서 540개 설명이 “을(를)” 형태를 사용한다. 예: “켈프을(를) 보유하세요”, “현무암 삼각주을(를) 방문하세요”. 이름마다 받침이 다르고 외래어·고유명사도 섞여 한국어 문장이 어색하다.

**수정 방향 제안:** 생성기에 한글 받침을 판별해 을/를, 이/가 등의 조사를 적용하거나, 조사 문제를 없애는 문형으로 다시 쓴다(예: “보유 아이템: 켈프”, “방문 대상: 현무암 삼각주”, “도감에 기록: ...”). 생성기 원본과 산출된 JSON5/문서 출력을 함께 갱신한다.

### 08-2 — 설명이 실제 제출/감지 과제를 다르게 말하는 사례 (P1)

- C1-06 민물 마시기는 민물 병 1개를 소비하는 아이템 제출 task다. 설명은 “마셔 갈증 회복 효과를 확인”하라고 하지만 음용 행동/갈증 회복을 감지하지 않는다. 인벤토리의 병을 제출해도 완료된다.
- C4-21d 낚시 심화·특수 훅 설명은 특수 훅을 제출한다고 하지만 task는 special_fish_hook 발전과제이며, 발전과제는 훅을 인벤토리에 얻으면 달성된다. 아이템은 제출/소모되지 않는다.
- C2-24 열대의 맛은 망고·파인애플 제출 과제다. 도감 기록을 위해 먼저 먹으라고 덧붙인 것은 유용하지만, “제출 전에 먹기”를 명시해야 퀘스트 진행과 수집 목표의 순서를 이해하기 쉽다.

**수정 방향 제안:** task가 실제로 검증하는 행위를 문장에 맞춘다. 실제 음용을 가르치려면 사용 이벤트/발전과제로 바꾸거나 “병을 제출하면 완료”로 문구를 고친다. 특수 훅은 “특수 훅을 한 번 얻으세요”라고 표현한다. 자동 감지 추가는 기능 설계 단계에서 판단한다.

### 08-3 — 수동 체크는 투명하지만 설비 핵심 행동을 증명하지 못함 (P1, 학습 경험)

T0의 HUD/JEI/지도/도전과제 확인, C3의 경유지 표시·상점 열기, C5의 증류 라인·정수 라인·급수 시설·부엌/수확물 파이프 연결은 체크마크다. 설명이 “자동 감지되지 않아 직접 체크”라고 밝힌 곳도 있다. 조작 안내용 체크마크는 괜찮지만, 퀘스트를 완료해도 실제로 파이프가 연결됐거나 기계가 생산했다는 증거가 남지 않는다.

**수정 방향 제안:** 가능하면 한 번의 생산/산출 아이템/블록 상호작용/발전과제/통계를 감지하는 목표로 대체한다. 물리 배치 자체를 읽기 어렵다면 목표를 “민물 병/증류수 출력물을 얻기”처럼 결과물로 바꾸고 설비 구성은 설명에서 가르친다. 화면 열기/설정 확인처럼 감지가 불가능한 행동은 체크마크를 유지하되 “확인 뒤 체크”라는 표현을 통일한다.

### 08-4 — 번들명과 일반 명사 사이의 띄어쓰기를 통일할 필요 (P2)

번들 품목 설명은 “「물의 네 얼굴」꾸러미에 필요한 물품입니다”처럼 묶음명 뒤 보통 명사가 붙어 반복된다. 제목/설명에서 장 번호, 외래 모드명, 아이템 공식 이름도 괄호와 영문 병기를 혼용한다. 의미는 이해되지만 반복되면 자동 생성문 느낌이 강해진다.

**수정 방향 제안:** “「물의 네 얼굴」 꾸러미”처럼 공백을 두고, 모드/아이템 공식명은 JEI와 같은 이름을 우선한다. 용어집에 한글 표기와 원문 병기 규칙을 두고 제목에는 장/기능을 짧게, 설명에는 다음 행동을 둔다.

## 우선 조치 제안

1. 생성기 문안 규칙의 조사 문제를 고치고 자동 문구를 다시 생성한다.
2. 설명과 감지 방식이 다르게 말하는 C1-06, C4-21d부터 task/문안을 맞춘다.
3. 설비 학습 목표는 가능한 경우 구성 감지보다 결과물/상호작용으로 바꾼다. 사용자는 특히 이 감지 공백을 개선하고 싶다고 밝혔다.
4. 초반 보상과 도감 100% 보상은 자원/거래 가치와 함께 재확인하고, P-10 최종 보상은 기획 문서와 실제 목적을 맞춘다.

## 회차 결론

개별 본편 퀘스트는 실제 대상과 다음 행동을 구체적으로 적으려는 흐름이 좋고, 보상도 대체로 다음 단계 재료/용기/탐험 보급에 맞춘다. 우선 수정은 **08-1 540개 조사 자동 생성문**, **08-2 설명/감지 불일치**, **08-3 설비 수동 체크의 결과 감지 전환**, **08-4 P-10 기념 보상과 기획 문서의 일치**다. 일괄 문안 변경은 원본 생성기와 재생성 산출물에서 함께 검토하고, 플레이 난이도는 14번에서 확인한다.
