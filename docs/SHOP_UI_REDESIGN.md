# 공급소 상점 UI 개편안

> **역사 기록 (패치 6.6)**: 매입 계산대(패치 5.4) 구현 이전의 개편안. 현재 동작은 `docs/SHOP_SUPPLY_POST.md`가 정본이다.

## 현재 구현

QShop 1.8.4는 인벤토리 컨테이너가 아니라 자체 `Screen`을 연다. 현재 연동은 설정된 고정 구매·매입 항목을 만들며, 거래 API도 설정된 상점 항목을 기준으로 한다. 판매 칸에 임의 아이템을 놓아 가격을 계산하고 매입하는 기능은 없다.

포함된 QShop API에는 `IItemHandler` 기반 구매·판매 처리와 통화 서비스가 있어 커스텀 메뉴에서 재사용할 수 있다. 다만 임의 아이템 견적에는 RS 쪽 가격·검증 계층을 추가해야 한다. 따라서 인벤토리형 화면으로 바꾸려면 설정 변경만으로는 부족하고 Realism Survival의 메뉴·화면 구현이 필요하다.

## 권장 이용 흐름

1. 공급소 NPC를 우클릭한다. NPC 이름으로 전문 분야를 식별한다. 공급소 상점의 직접 열기 명령은 차단되어 있다.
2. 첫 화면에서 **구매** 또는 **판매**를 고른다. 현재 기후·계절·전문 분야와 잔액을 보여준다.
3. 구매 화면은 해당 NPC의 시즌별 상품을 보여준다. 상품을 선택하면 개당 가격, 수량 조절, 합계, 일일 제한을 표시한 뒤 구매를 확인한다.
4. 판매 화면은 한 개 이상의 임시 보관 칸을 제공한다. 아이템을 놓으면 매입 수량, 단가, 총액, 거절 사유를 표시하고 거래 확정 전에 견적을 확인하게 한다.
5. 화면을 닫으면 임시 아이템을 플레이어에게 돌려준다. 서버는 판매 확정 때 견적·아이템 수량·제한을 다시 확인한다.

## 구현 기준

- `supply_shop_seasons.json`을 기후·계절별 구매가와 매입가의 기준으로 유지한다.
- 등록된 상품은 기존 `SupplyStock` 분류와 매입가 계산을 재사용한다.
- 등록되지 않은 아이템의 가격 정책을 명시한다. 첫 구현은 등록/태그된 아이템만 받고, 그 외에는 “매입 목록에 없는 품목”으로 안내하는 방식을 권장한다. 미등록 아이템을 임의로 광물로 분류하지 않는다.
- 커스텀 데이터, 내구도, 마법 부여, 물약 내용물이 있는 스택은 해당 속성의 가격 규칙이 정해질 때까지 거절하거나 제외한다.
- 견적·아이템 인출·거래 횟수 제한·통화 처리는 서버에서 확정한다. 오래된 클라이언트 가격을 이용하지 못하도록 확정 시 다시 계산한다.
- 잔액은 QShop 통화 서비스와 기존 SG Economy 연동을 사용하고, 임의 아이템 가격 계산은 RS가 담당한다.
- 기존 플레이어별 거래 횟수 제한을 판매대에도 적용한다.

## 권장 구현 순서

1. 현재 고정 상품을 유지하면서 QShop 화면을 첫 화면과 구매 카탈로그로 교체한다.
2. 등록된 매입 상품부터 견적과 확정 단계를 갖춘 판매대를 추가한다.
3. 가격과 제한을 검토한 뒤 등록 목록 또는 저가 기본 가격 정책을 확장한다.

이 구조는 계절별 상품 선택을 유지하면서 판매 과정을 예측 가능하게 만든다. 모든 모드 아이템을 의미 있는 가격으로 매입한다고 약속하기보다, 등록된 상품과 가격 근거를 먼저 명확히 한다.
