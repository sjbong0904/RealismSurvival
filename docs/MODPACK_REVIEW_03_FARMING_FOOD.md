# 전수 검토 03 — 농사·계절·식량 연결

검토일: 2026-10-21  
검토 기준: 개발 `runClient` 기본 리소스와 코드의 정적 추적. 실제 게임에서 성장 속도·계절 전환·수확량을 재지 않았다.  
범위: 작물 성장 배율, 빛·바이옴·계절 조건, Serene Seasons 선택 연동, 식량·음료 생존 데이터와 다음 재료 경제 회차의 연결.

## 요약

작물 성장에는 바이옴, 광량, 계절, 강우 수분 보너스, 해안 염수 혼합을 곱하는 데이터 기반 규칙이 있고, Farmer’s Delight 작물도 일부 지정되어 있다. 작물 규칙은 서버 쪽 이벤트에서 적용되며 Serene Seasons가 있을 때 자체 계절 성장 규칙과 강우 보너스를 생략한다. 채소·고기·생선·조리 음식은 54개 음료 정의로 갈증/체온 데이터와 연결되어 있다.

현재 보이는 주된 UX/밸런스 위험은 기본 온대 바이옴의 계절 성장 데이터에 범용 겨울 감속이 있어도, Serene Seasons가 켜지면 이 모드의 계절 규칙을 통째로 건너뛴다는 점이다. 따라서 Serene Seasons의 해당 버전·설정·작물 호환이 실제로 같은 강도의 계절 제약을 제공하는지 확인해야 한다. 또 성장 배율은 작물 성장 이벤트에서 `GROW`를 강제할 수 있으므로, 큰 배율을 여러 환경 보너스가 함께 적용할 때 의미를 플레이에서 확인해야 한다. 이번 회차에는 코드 수정이나 게임 검증을 하지 않았다.

## 확인한 현재 구성

- `CropGrowthHandler`는 작물 성장 전 이벤트에서 바이옴 배율 × 빛 배율 × 자체 계절 배율 × 비 수분 보너스 × 해안 염수 혼합 배율을 계산한다.
- 황무지/사막 배율은 `0.5`, 정글 내 기본 작물 일부는 `1.35`다.
- 자체 계절 데이터는 밀·비트 `봄/가을 1.25`, 당근·감자·베리 `여름/가을 1.2`, 멜론·호박 `여름 1.35`, 겨울 전체 작물 `0.45`다.
- Farmer’s Delight 데이터는 양배추·양파 `봄/가을 1.25`, 토마토·벼 계열 `여름 1.3`이며 모드 로드 조건이 붙어 있다.
- 햇빛 선호 작물은 광량 0–5에서 성장 차단, 6–8에서 `0.35`, 9–11에서 `0.7`, 12–13에서 `1.0`, 14–15에서 `1.3`이다. 그늘 선호 그룹은 낮은 광량에서 최대 `1.25`, 12 이상에서 차단된다.
- 자체 달력은 365일을 봄 91일·여름 92일·가을 91일·겨울 91일로 나눈다. Serene Seasons를 읽을 수 있으면 외부 계절을 우선한다.
- 식량 음료 데이터는 기본 작물, Farmer’s Delight, Fish of Thieves 및 Aquaculture 일부 식품을 다룬다. 코드의 매칭은 우선순위가 높은 일치 정의 하나를 선택한다. 이번 회차에는 아이템별 전체 수분량과 레시피 비용을 가격표처럼 전수 대조하지 않고, 04번에서 자원 흐름과 함께 본다.

## 발견사항과 수정 방향

### 03-1 — Serene Seasons 활성 시 커스텀 작물 계절 규칙 전체가 생략됨 (P1, 구성 의존)

`SereneSeasonsBridge.present()`가 참이면 `cropSeason` 규칙뿐 아니라 자체 계절의 강우 수분 보너스도 함께 생략된다. 외부 모드가 바닐라 작물에 겨울 제한을 적용하더라도 Farmer’s Delight 작물에 같은 제한이 있는지, 설정에서 작물 계절성이 꺼질 수 있는지, 현재 번들 버전에서 실제 이벤트가 동작하는지는 이 코드만으로 보장되지 않는다. 그 경우 밀·비트의 봄/가을 보너스, 작물 전반의 겨울 `0.45`, FD 작물의 지정 계절 보너스가 사라질 수 있다.

**수정 방향 제안:** 지원 대상 Serene Seasons 버전에서 각 작물군의 겨울 성장/성장 차단 여부를 확인한다. 외부 모드가 일부 작물만 처리한다면 중복 방지 대상 작물군을 좁혀 직접 계절 규칙을 유지하거나, 의도적으로 외부 모드 규칙에 맡기는 설정을 명시한다. 모드가 없거나 API 조회에 실패했을 때의 자체 달력 전환도 사용자 안내에 적는다.

### 03-2 — 환경 배율의 합성 결과가 누적되어 의도보다 커질 수 있음 (P2, 수치 검증)

여러 환경 규칙을 곱한다. 예를 들어 정글 `1.35`와 햇빛 작물의 고광량 `1.3`만 겹쳐도 계절/해안 보정 전 `1.755`가 된다. `CropGrowthHandler`는 1 초과 시 `GROW` 결과를 확률적으로 설정한다. 각 개별 JSON은 0–10 범위를 허용해 데이터 수정 시 합성 배율이 크게 뛸 여지도 있다.

**수정 방향 제안:** 데이터 검토 단계에서 가능한 중첩 조합의 최소/최대 배율을 표로 계산하고, 성장 단계별 실제 시간 기준으로 허용 범위를 정한다. 설계 의도가 백분율 합산이라면 곱셈 대신 가산 보정 또는 최종 상한을 검토한다. `GROW`가 바닐라의 수분/성장 조건 중 어떤 검사를 우회하는지는 대상 NeoForge 버전의 이벤트 의미와 실제 플레이로 확인한다.

### 03-3 — 모든 기본 작물에 적용되는 명시적 계절/빛 그룹이 제한적임 (P2, 발견 가능성)

기본 계절 규칙은 식량 작물 일부에만 지정돼 있고, 나머지는 겨울 기본 감속 외에는 `1.0`으로 남는다. 빛 규칙 역시 별도 그룹에 들어간 작물에만 적용된다. 플레이어에게는 계절 시스템이 모든 작물에 작동하는 듯 보일 수 있지만, 실제 규칙은 작물군마다 다르다.

**수정 방향 제안:** 계절별로 의도한 작물 범위를 표로 확정하고, 규칙이 없는 작물을 “계절 영향 없음”으로 볼지 누락으로 볼지 기록한다. 특히 나무 작물, 덩굴/줄기 작물, 모드 농작물의 적용/제외를 정리한 뒤 퀘스트나 JEI/가이드에서 재배 조건을 안내한다.

### 03-4 — 식량 데이터는 폭넓지만 작물 자립과 처리 체인의 균형은 다음 관점에서 확인 필요 (P2, 연계)

갈증 회복량은 수분 많은 작물·과일·조리 식품에 분산돼 있고, 생식 재료/건조 식품/해산물 일부는 갈증 페널티를 받는다. 다만 작물의 실제 성장률, 수확량, 씨앗 재투입, 요리 재료 소모, 보존 방식, 공급소 가격을 하나의 순환으로 비교해야 초반 식량 자립이 너무 쉽거나 지나치게 강제되는지 판단할 수 있다.

**수정 방향 제안:** 04번에서 대표 작물별 “씨앗/재료 → 수확 → 생식/조리/보존 → 갈증·체온 회복 → 부산물/거래” 흐름을 비교한다. 식량 퀘스트 보상도 해당 시점의 재배가 이미 시작 가능한지와 함께 대조한다.

## 장점

- 농사 규칙이 데이터팩으로 분리되어 작물/바이옴/계절/광량을 코드 수정 없이 조정할 수 있다.
- 바이옴·빛·계절·수분·염수 규칙이 성장 이벤트 한 경로에서 합성되어 결과 추적이 가능하다.
- Farmer’s Delight 작물에는 모드 로드 조건을 붙여 선택적 의존성이 적용돼 있다.
- Serene Seasons를 계절 권위자로 고려해 두 개의 계절 페널티가 무조건 중복 적용되는 상황을 피하려는 의도가 보인다.
- 식량이 갈증과 체온 시스템에도 연결되어 재배와 생존 루프가 분리되어 있지 않다.
